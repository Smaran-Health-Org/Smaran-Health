## Findings and focused changes

Seven older pgTAP files still called the pre-0100 positional three-argument
walk-in function, or inspected that removed signature. The key was interpreted
as a timestamp, producing the baseline failures and incomplete plans. Updated
calls use named patient, doctor, and idempotency-key parameters; the optional
time and acknowledgement defaults retain the original immediate-walk-in intent.
Assertions were retained rather than weakened.

After correcting those tests, `0076` still aborted on the original receipt's
post-merge retry. A dedicated 14-assertion regression reproduced two defects:

- A receipt replay using the original patient identity failed after an authorized
  patient merge, even though the original Appointment and Encounter survived.
- A request with an existing key and a changed explicitly selected time silently
  returned the first visit.

Migration `0107_walk_in_retry_identity.sql` replaces the current authority
function without editing historical migrations. It allows a same-clinic source
identity to reach the serialized receipt check, while requiring an unmerged
patient for any new command. It compares a supplied time with the immutable
creation receipt, rather than the appointment's mutable current time. Existing
NULL-time immediate replay behavior is preserved. It neither rewrites original
receipts nor moves/deletes appointments, notes, documents, or history.

The regression failed assertions 3 and 6 before the fix and passes all 14 after
it. It also proves clinic isolation, canonical ownership with original identity
provenance, one Appointment/Encounter/check-in audit, rejection of a canonical
identity claiming another request, and rejection of new work for merged-away
identities.
